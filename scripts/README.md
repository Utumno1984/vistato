# Test removal guard

Detects tests that disappear or are renamed between a base and HEAD, which would otherwise hide
a removed feature without any failing test. CI integration is a separate ticket (#14).

## Scripts

- `tsx scripts/list-tests.ts --root <dir>`: prints a sorted JSON array of
  `{runner, project, file, name}` for vitest and Playwright. `file` is relative to `<dir>`; no
  line/column and no absolute paths. Exit 2 if a command fails or the output is malformed.
  - Vitest: `vitest list --json --staticParse=false` with `cwd=<dir>`, so it uses that checkout's
    configuration (a PR changing include/exclude is detected). The static parser (the Vitest 5
    default) invents tests from ordinary calls such as `testSql()(row)` or `tests.some((x) => ...)`
    and misses generated ones, so the files are really collected (imported), not run.
  - Collection would run each project's `globalSetup` (here: migrations and seed on the test
    database). The script therefore loads the repository's config through a temporary wrapper
    config (in the OS temp dir, nothing is written to `<dir>`) that drops every `globalSetup`, top
    level and per project. Nothing else of the config is changed. `DATABASE_URL` and
    `TEST_DATABASE_URL` are also set to empty for the child processes, so test files imported
    during collection cannot reach a database. No browser is needed for Playwright (`--list`).
  - Test files are imported: top-level side effects of a test file do run. Keep them free of I/O.
- `tsx scripts/check-test-removal.ts --base <file.json> --head <file.json> [--labels <json|a,b> | --labels-file <path>] [--body-file <path>]`
  - exit 0: nothing missing, or missing tests with a valid exemption (listed as `::warning`);
  - exit 1: tests missing without a valid exemption (listed as `::error`, at most 50 plus the total);
  - exit 2: tool error (empty or malformed list, unreadable file, bad arguments).
  - `--labels` is never a file name: a JSON array (strings or `{name}` objects), the object
    `{"labels": [...]}` printed by `gh pr view --json labels`, or a comma separated string.
    `--labels-file` reads the same formats from a file.
  - The PR body is untrusted: it is only read from a file and parsed as text.
- `npm run test:guard -- --base-ref <ref> [--labels ...] [--labels-file ...] [--body-file ...]`:
  local comparison between `<ref>` (default `origin/main`, resolved to a commit and checked out in
  a temporary `git worktree`, removed on exit, SIGINT and SIGTERM) and the working copy. A ref
  starting with `-` is refused.

## Rules

- A test id is `runner + project + file + full name`. Comparison is by occurrence count: two
  identical tests in base and one in HEAD means one is missing. Moving a test to another file or
  renaming it counts as removal; added tests are always fine.
- A test run by two Playwright projects counts twice.
- **Test names must be deterministic.** Names containing a date, a random value or any generated
  data change at every run and produce false positives. `test.each` rows are expanded by the real
  collection into one test per row; the row values are part of the name.
- The full name joins the titles of nested `describe`s and the test with `" > "`. This is
  ambiguous: a test titled `a > b` and a test `b` inside `describe("a")` have the same name (and
  the same id). It can only hide a removal when both exist in the same file and project; avoid
  `" > "` in titles.
- Exemption: label `rimozione-funzionalita` **and** a section `## Rimozione funzionalità` in the PR
  body. The text counts only letters and digits (at least 30). Not counted: HTML comments,
  invisible format characters (zero-width spaces and the like), sub-headings, list and quote
  markers, and placeholder lines (`...`, `TODO`, `TBD`, `N/A`, `xxx`, lines starting with
  "Descrivi", lines made only of `[...]` or `<...>`). The heading is matched ignoring case,
  accents and extra spaces, and the section ends at the next heading of level 1 or 2.

## Blind spots

The guard compares names, not behaviour. It does not see:

- tests moved into a helper imported by several files, or generated by a `for` loop or an alias
  (`const it2 = it`) in a way that keeps the same names: real collection sees what is generated,
  but a loop that silently runs fewer iterations is only visible as removed names;
- `it.each`/`describe.each` rows: removing one row removes one name and is reported, but changing
  the value of a row (e.g. `1` to `2`) renames the test and is reported as a removal plus an add;
- `.skip`, `.only`, `.fixme`, `test.todo` and weakened or deleted assertions (left to review);
- a test whose body was emptied.

## Notes for the CI job (ticket #14)

The job that runs the guard must not receive secrets and must not use `pull_request_target`: it
checks out and executes code (test files are imported, configs are loaded) of the pull request.
Use `pull_request` with read-only permissions, and pass the labels and the PR body as files, never
interpolated in a shell command.
